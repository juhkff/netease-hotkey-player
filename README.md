# 网易云一键播放 · 热键设置

[![Windows build](https://github.com/juhkff/netease-hotkey-player/actions/workflows/windows-release.yml/badge.svg)](https://github.com/juhkff/netease-hotkey-player/actions/workflows/windows-release.yml)

[下载 Windows x64 免安装包](https://github.com/juhkff/netease-hotkey-player/releases/latest) · [版本说明](docs/releases/v1.0.6.md)

一个挂在后台的 Windows 托盘小程序：**按一个组合键（任意界面都生效），网易云立刻开始播放你指定的那首歌，并且从你指定的秒数开始。**

**v1.0.6 实验功能：监听游戏事件**。主窗口或托盘菜单的“游戏事件…”可以添加“游戏 → 事件 → 歌曲”规则，逐条启停，设置歌曲起点和触发延迟。当前仅有一个内置游戏适配：**《罪恶装备·奋战》凯发动龙装**；其他游戏和事件需增加对应适配，不能仅靠填写名称监听。

规则中的 **1P、2P 是两个独立勾选框**，可以只选一方或同时选择。这里指开局角色槽位，角色换到画面另一边后不变；尚未自动识别联网时自己操控的一方。双边选择同一规则时，在该规则的延迟窗口内收到双方事件会合并成一次播放请求。不同的启用规则不能覆盖同一个游戏事件与角色，以免争抢歌曲。

使用时进入“游戏事件…”→“添加规则”→选择事件、勾选监听角色→“选择歌曲…”搜索歌曲→设置起点和延迟→保存，并勾选“启用游戏事件监听”。首次升级默认关闭，不改动已有热键。热键和游戏事件共用同一个播放服务与中断点；启用点歌机模式后，原复位键也能恢复事件播放前的音乐。托盘“暂停全部触发”同时暂停热键与事件；关闭设置主窗口仍在托盘运行。

实时游戏状态放在“游戏事件…”页面的规则表下方，可查看连接状态及 1P、2P 当前动作。打开此页面期间仍按已保存的规则刷新状态，同时暂停事件自动切歌；保存或取消后恢复自动触发。

GGST 当前只读支持本机已验证 EXE（Steam build 24797162）；版本校验失败会停止识别。**训练场已实测触发切歌与播放复位，联网行为仍待验证**，未自动处理败北停歌、原游戏 BGM 音量或淡入。原游戏声音 Mod 没有自动卸载，同时保留会叠加。默认延迟 0.4 秒是发出播放请求前的等待，客户端切歌和缓冲另有耗时。此功能不依赖独立的 `GgstMusicProbe.exe`。

连接与搜索修复：搜索会确认“单曲”标签实际选中，并在异步结果重建标签时重新检查；播放命令失败会记录完整错误并丢弃缓存连接，下一次命令重新连接客户端，避免重开客户端或页面超时后一直沿用失效连接。这些改动不能证明已覆盖所有间歇性故障，实际错误见 `logs/app.log`。

复位修复：不再假设“上一首”一定能回到中断的歌曲。先做有限回退，原曲不在队列或回退失败时通过客户端原生列表重新加载，再在暂停状态下恢复位置、队列和原播放状态。复位执行上限 20 秒，界面等待上限 30 秒（包括排队）；超时保留当前播放服务内的中断点供重试。复位期间不重复排队，也暂不接受新的音乐触发，但原键盘输入仍正常透传。中断点仍属于当前播放服务，重启应用后不保留。

切歌优化：正常播放不再预先等待额外的权限查询，暂停和跳转改为确认客户端状态后立即继续；恢复播放后仍检查进度是否真实前进。搜索页标题与列表不一致时优先换一个有效关键词，避免反复等待旧列表。播放请求同样有 20 秒执行上限和 30 秒界面等待上限；复位可中断尚未完成的播放请求，并保留原中断点。`logs/app.log` 记录毫秒时间和各播放步骤耗时，便于区分规则延迟、搜索加载、定位起点和播放验证；网络缓冲仍会影响实际切歌速度。

**v1.0.2 按键透传**：播放键和复位键只监听、不拦截，游戏和输入框仍能收到原来的按键。长按只触发一次音乐操作，松开后再按才能再次触发；编辑热键时暂不触发音乐。单键和组合键均支持，例如 `P` 播放、`O` 复位，同时保留 P、O 原本的功能。

**v1.0.3 符号键修复**：修复捕获出的 `Oemplus`、`OemMinus`、`Oemtilde`、小键盘和媒体键等名称无法解析的问题。按键框录制出的名称现在可以直接保存；单独按 Ctrl、Shift、Alt 时会继续等待主键。

**v1.0.4 搜索修复**：修复中文关键词传给播放服务时的编码不一致，以及网易云已返回歌曲、添加窗口却显示“没搜到”的问题；兼容播放服务返回的实际集合类型，连续搜索时只显示最后一次请求的结果。

**v1.0.5 切歌提速**：目标歌曲已在客户端列表中显示时直接双击对应歌曲行，省去重复搜索；歌曲信息缓存十分钟，减少重复请求；缩短搜索和播放状态的轮询间隔。目标不在页面中时仍保留完整搜索流程。网络取流和客户端缓冲仍有耗时。

**客户端兼容性**：支持普通 Windows 安装版及 Microsoft Store 版，均需带本地调试端口启动。普通版直接启动 `cloudmusic.exe`，商店版使用 Windows 应用激活接口；自定义安装路径可从正在运行的客户端识别并缓存。当前修复在本机商店版 3.1.23 上验证，其他版本仍取决于其调试端口和页面结构是否兼容，不能保证每个新版客户端均适用。

示例：按 `Ctrl+Alt+1` → 立刻播《起风了》，从第 15 秒开始。

> **v1.0.1 修复版支持免安装运行**：Windows x64 程序包自带 `runtime/node.exe`，完整解压后直接双击 `NcmHotkey.exe`，不需要在系统里安装 Node.js，也不需要配置 PATH。内部仍使用随包运行时执行播放服务。旧的 v1.0.0 包没有自带运行时；请确认使用的是新版构建。

**能干什么**

- 🔘 **一键播放**：任意界面按下组合键 → 切到指定歌曲、跳到指定秒数，误差 ±0.1 秒
- 🎤 **点歌机模式**：打断正在放的歌 → 播一段别的 → 按复位键**回到刚才中断的位置**继续，连待播放队列都原样还原
- 🎵 **搜歌不用记 ID**：在界面里搜歌名（带歌手/专辑更准），选中即可
- 🔕 **完全静默**：不弹通知、不弹对话框，只留一个托盘图标
- 💎 **VIP 歌曲正常播**：走的是网易云客户端自己，不是第三方取流

**怎么做到的**（一句话）：用 `--remote-debugging-port` 让网易云开出调试端口，通过 CDP 在它的页面里驱动界面 —— 搜索、双击播放、改播放位置；Windows 键盘监听器识别音乐按键后立即传递原始按键，音乐操作异步执行。

> ⚠️ 前提：网易云客户端必须用**带调试端口的方式**启动（装好后桌面上会多一个专用快捷方式）。
> 详见 [六、出问题了怎么办](#六出问题了怎么办)。

## 一、直接开始用

### 1. 打开设置界面

- 免安装模式：在完整解压的新版目录里双击 `NcmHotkey.exe`，保留旁边的 `runtime`、`lib` 和 `worker.mjs`。
- 双击桌面上的 **网易云热键**（或开始菜单里找），也可以从右下角托盘图标双击打开。
- 窗口长这样：

  ```
  ┌─ 网易云一键播放 · 热键设置 ─────────────────┐
  │ [添加] [编辑] [删除] [试一下] [启动网易云] [打开目录] │
  ├─────────────────────────────────────────────┤
  │ 按键        歌曲                    开始位置  状态 │
  │ Ctrl+Alt+1  起风了 / 冯沁苑(买辣椒也用券)  0:15   待命 │
  │ Ctrl+Alt+2  勋章 / 鹿晗              1:30   待命 │
  ├─────────────────────────────────────────────┤
  │ 程序会缩到右下角托盘里继续生效。双击列表里的一行可以修改。│
  │ 已连上网易云（端口 9229）                        │
  └─────────────────────────────────────────────┘
  ```

### 2. 用带调试端口的方式打开网易云

**这一步是必须的**：网易云必须用桌面上的 **「网易云音乐(带热键)」** 快捷方式启动，
或者在设置界面里点 **「启动网易云」** 按钮。

普通方式（开始菜单 / 任务栏图标）打开的网易云**没有**那个调试端口，热键按下去会没反应。
如果它本来就开着，先退干净，再用专用快捷方式打开。

状态栏显示 **「已连上网易云（端口 9229）」** 就说明连上了。

### 3. 按键

免安装模式首次启动时，先点“添加”设置自己的歌曲和按键。`config.example.json` 仅供参考，不会自动替换已有配置。

例如设置 `Ctrl+Alt+1` 播放《起风了》第 15 秒后，切到其他窗口按该组合键即可播放。首次搜索及客户端加载可能需要等待，同一首歌再次触发通常更快。

> 第一次按会慢一点（要重新加载歌曲），同一首歌连按会快很多。

## 二、加一首自己的歌

点 **「添加」**，然后按顺序填：

| 位置 | 说明 |
| --- | --- |
| **按键** | 点进那个框，直接按你想用的组合键就行，比如 `Ctrl+Alt+7`、`Ctrl+Shift+F9`、`Alt+F8` |
| **搜歌** | 输入歌名（最好带上歌手，例如 `晴天 周杰伦`），点「搜索」 |
| **结果列表** | 从下面挑出你要的那一首，点一下选中 |
| **开始位置** | 从第几秒开始播。填 `0` 就是从开头播 |
| **备注** | 会自动填上「歌名 / 歌手」，可以自己改，只影响列表和托盘提示的显示 |

点「确定」保存，**立刻生效，不用重启**。

符号键会显示 Windows 的按键名，例如主键盘的 `=/+` 键显示为 `Oemplus`，减号键为 `OemMinus`。小键盘的加号是另一个键，显示为 `Add`；小键盘数字支持 `Num0`～`Num9` 和 `NumPad0`～`NumPad9`。需要 Shift 的组合请一起录制，例如 `Shift+Oemplus`。手动填写时，`+`、`Ctrl++` 也可分别表示 `Oemplus`、`Ctrl+Oemplus`，不会自动添加 Shift。

### 为什么要带歌手 / 专辑名

网易云的搜索结果里翻唱特别多。只搜「晴天」，前 180 条都找不到周杰伦的原版。
加上专辑名（`晴天 周杰伦 叶惠美`）原版就排在第 1 条了 —— 所以搜歌时**可以在歌名后面加上歌手或专辑名**。

选中结果后，对话框里会显示它对应的歌曲 ID；这个 ID 就是保存进配置的东西，不受搜索结果排序影响。

## 三、其他按钮

| 按钮 | 作用 |
| --- | --- |
| **编辑** | 改选中的那一条（也可以直接双击列表里的一行） |
| **删除** | 删掉选中的那一条 |
| **试一下** | 不按热键，立刻播放选中的那一条，用来验证配得对不对 |
| **启动网易云** | 用带调试端口的方式启动网易云 |
| **打开目录** | 打开程序安装目录（看配置、看日志） |

托盘图标右键菜单里还有：

- **复位到中断位置** —— 等于按一下复位键（详见下一节）
- **复位到中断位置** —— 等于按一下复位键（详见下一节）
- **暂停全部热键** —— 临时让所有热键失效（比如某个键跟游戏冲突时）
- **退出** —— 真的退出程序

点窗口右上角的 × **不会退出**，只是缩到托盘里继续生效。

## 四、点歌机模式：打断 → 播片段 → 按复位键回到原处

界面底部有一个 **「点歌机模式」** 开关（默认开着）。它就是为「正在放一首歌，临时插播一段别的，播完还要回到刚才那首歌、那个位置」这种场景做的。

**用法**

1. 勾上「点歌机模式」，在右边设一个 **复位键**（默认 `Ctrl+Alt+0`，点「设置」然后直接按你想用的组合键）。
2. 正常在放歌。想插播时，按某个**片段键**（比如 `Ctrl+Alt+2` → 《勋章》第 90 秒）。
   - 程序会**先悄悄记下现在这首歌、放到第几秒、待播放队列长什么样**，然后再切过去。
   - 连按两个片段键也不会把中断点弄丢：复位时回的是**最早那次打断前**的位置。
3. 插播完，按 **复位键** → 回到刚才那首歌，**从刚才那个位置无缝继续**，播放/暂停状态也保持一致。

**队列会被完整还原。** 双击播放会把片段那首歌插进「待播放」列表，复位时程序会把整份队列按原样灌回去 —— 实测复位前后队列逐项一致（`lost=[] extra=[]`）。

**几个细节**

- 界面上你看不到中断点？看状态栏，连上客户端后会显示 `中断点：起风了(林俊杰) @ 1:46`。
- 还没按过片段键就按复位键，会提示「还没有中断点」。
- 复位先尝试有限次数的 «上一首»；无法回到原曲时，改用原生歌曲列表重新加载，再恢复位置和队列。
- 不想要这套行为，把「点歌机模式」的勾去掉即可，片段键就退化成单纯的「切歌并跳转」。

## 五、开机自启

已经装好了：开机时会自动在后台启动，托盘里有图标。

**它是完全静默的**：不弹任何 Windows 气泡通知、不弹对话框，也不会闪出窗口 —— 只留右下角一个托盘图标，热键直接生效。
按了热键之后想看结果，就把鼠标移到托盘图标上，或双击图标打开窗口看状态栏。

> 用 `--tray` 启动就是这个效果（开机启动项已经带上了）。手动双击 exe 不加参数的话，会正常显示设置窗口。

想要回气泡通知？把安装目录 `config.json` 里的 `"notify": true` 加上，重启程序即可。

不想要的话，把启动文件夹里的 `网易云热键.lnk` 删掉即可：
按 `Win+R` 输入 `shell:startup` 回车，删掉里面那个快捷方式。

## 六、出问题了怎么办

程序日志在安装目录的 `logs\app.log`。

**启动时报「没有与此对象关联的进程」？**

- 这是旧版在播放服务启动失败后访问未启动 `Process.HasExited` 的错误，不需要开启 JIT 调试。
- v1.0.1 修复了启动失败清理、进程状态检查、通信失败及退出后待处理回调的收尾。
- 新版优先使用随包的 `runtime/node.exe`；缺少运行时会在状态栏和日志中显示原因。不要只复制 EXE，须保留完整目录。
- 支持 Microsoft Store 版网易云：通过 Windows 应用激活接口传入调试参数，避免直接执行 `WindowsApps` 内的程序时出现“拒绝访问”。工具可识别已注册的商店版安装，也可从正在运行的客户端识别路径并缓存到 `cloudmusic.txt`。首次连接前需从托盘彻底退出网易云，再点击工具里的「启动网易云」。

**按了没反应？**
- 看状态栏是不是「已连上网易云（端口 9229）」。不是的话，说明网易云不是用专用快捷方式开的 —— 退干净重开。
- 看列表里的「状态」列：显示「注册失败(1409)」表示这个组合键被别的软件占了，换一个。

**提示「这首歌当前账号放不了」？**
- 这首歌在你这个账号 / 地区放不了（版权限制）。判断依据是网易云返回的资源状态 `st`，小于 0 就是放不了。这跟你有没有会员无关。

**网易云整个卡住、进度条不动了？**
- 重启一下网易云（退干净，再用专用快捷方式打开）。

## 七、它是怎么做到的

1. **网易云是 Chromium 内核的程序**。用 `--remote-debugging-port=9229` 启动后，它开了一个标准调试端口。
   程序通过这个端口（CDP 协议）在客户端页面里执行代码：读播放状态、驱动界面。
   这就是为什么必须用桌面上那个专用快捷方式启动 —— 普通方式启动的网易云没开这个端口。

2. **切歌**：把「歌名 + 歌手 + 专辑」填进客户端自带的搜索框 → 切到「单曲」标签 → 按歌曲 ID 找到那一行 → 派发一次合成的双击。
   （这是唯一能让原生播放器**真正出声**的路径。试过直接往内部状态里注入歌曲，界面会显示在播，但音频永远不出声。）

3. **跳到指定秒数**：暂停 → 改播放位置 → 继续。实测误差在 ±0.1 秒以内。

4. **全局热键**：程序用 Windows 的 `RegisterHotKey` 注册组合键，所以切到任何窗口都生效。
   （网易云网页内部那套 `hotkeys` 只在它自己窗口里有反应，做不到这点。）

5. **读状态**：客户端的 Redux store 里就有歌曲 ID、时长、播放位置、播放状态，直接读，不用猜。

## 九、自己编译

不需要装 Visual Studio，使用 Windows 自带的 .NET Framework 编译器。构建免安装包：

```powershell
# 在仓库根目录
powershell -ExecutionPolicy Bypass -File tools\pack-release.ps1
```

首次打包会从 Node.js 官方下载固定版本的 Windows x64 运行时，校验官方 SHA-256，只提取 `node.exe` 和许可证到项目的 `out/runtime`。这一步需要网络；不会安装 Node、修改 PATH 或注册系统服务。

当前输出为 `dist/netease-hotkey-player-v1.0.6-win-x64.zip`。完整解压后可直接运行；`runtime/LICENSE` 包含运行时第三方许可。构建目录信息见 `dist/build-result.json`。

验证按键解析、搜索显示、进程启动失败与恢复、通信及运行时查找：

```powershell
powershell -ExecutionPolicy Bypass -File tools\test-worker-lifecycle.ps1
powershell -ExecutionPolicy Bypass -File tools\test-game-events.ps1
# 无需启动客户端的切歌流程测试
& .\out\runtime\node.exe --test tools\playback-performance.test.mjs tools\worker-recovery.test.mjs
PowerShell -ExecutionPolicy Bypass -File tools\verify-package.ps1
```

### GitHub Actions 自动发布

推送到 `main` 或提交 PR 会自动在 Windows 上获取并校验独立运行时、运行测试、构建并检查免安装包。测试不要求安装网易云，也不会播放音乐。

发布时先更新 `app/NcmHotkey.cs` 中的程序集版本（例如 `1.0.6.0`）、打包脚本的默认版本和相应文档，再推送同版本标签：

```powershell
git push origin main
git tag -a v1.0.6 -m "Release v1.0.6"
git push origin v1.0.6
```

标签版本必须与程序集版本一致。Actions 会通过全部检查后，自动上传 ZIP 与 SHA-256 文件并发布 Release；匹配的 `docs/releases/<标签>.md` 作为版本说明，没有该文件时生成默认说明。也可在 Actions 页手动运行 **Windows build and release**，输入已有标签重跑。发布使用仓库内置的 `GITHUB_TOKEN`，无需另配个人令牌。

原有的部署脚本仍可使用：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-app.ps1
```

它会：

1. 关掉正在运行的主程序
2. 用系统 `csc.exe` 编译主程序和三个游戏事件源文件为 x64 `NcmHotkey.exe`（`tools\pack-release.ps1` 已包含完整参数；不包含独立实验窗口）
3. 拷 `worker.mjs` 和 `lib\ncm.mjs` 到 `%LOCALAPPDATA%\ncm-hotkey\`
4. 把 node 的位置写进 `node.txt`
5. 重建桌面快捷方式和开机启动项（`config.json` 已存在就保留，不会覆盖你的配置）

> 旧的开发部署脚本仍会查找已有 Node。分发给普通用户请使用上面的 `pack-release.ps1` 免安装包，不要求用户安装 Node。

> .\tools\build-app.ps1 -Src '\\wsl.localhost\Ubuntu-26.04\home\ubuntu\projects\netease-hotkey-player'
